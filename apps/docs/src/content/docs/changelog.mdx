หน้านี้รวบรวมการเปลี่ยนแปลงทุกอย่างที่กระทบการใช้งาน API ได้แก่ GraphQL Schema, ข้อจำกัดการ Query, Endpoint, กฎการมองเห็นข้อมูล และ MCP Tool

เมื่อมีการเปลี่ยนชื่อหรือลบ Field ที่ผู้ใช้เข้าถึงได้ เราจะพยายามคง Field เดิมไว้ระยะหนึ่งพร้อมกับ Directive `@deprecated` ของ GraphQL และจะแจ้งการลบ Field นั้นเป็นรายการถัดไปในหน้านี้ ยกเว้น Relationship Field ที่ไม่สามารถมีอยู่คู่กับ Field ใหม่ได้ การเปลี่ยนชื่อจึงถูกระบุไว้ในหัวข้อ `Breaking` ทันที

## 2026-11-11

**Breaking**

- `bills: [Bill!]!` เปลี่ยนเป็น `bill: Bill` ใน `BillEnactEvent`, `BillRejectEvent`, `BillRoyalAssentEvent` และ `BillVoteEvent` เนื่องจากอีเวนต์เหล่านี้เป็นของร่างกฎหมายเพียงฉบับเดียว `bill` จะเป็น `null` เมื่ออีเวนต์ไม่มีร่างกฎหมาย และสร้างหรือลบได้ผ่านอีเวนต์เท่านั้น การเชื่อมหรือยกเลิกการเชื่อมกับร่างกฎหมายที่มีอยู่แล้วให้ทำผ่าน `Bill.events` แทน ส่วน `BillMergeEvent.bills` ยังคงเป็น List
- `named_entity` ใน `AlternateName` และ `AlternatePersonName` เปลี่ยนจาก List เป็น `NamedEntity` และ `Person` เพียงค่าเดียว
- ลบ `VoteEvent.bills` ที่เลิกใช้งานแล้วและไม่เคยมีข้อมูล ให้ใช้ `VoteEvent.bill_vote_events { bill }` แทน
- `Post.organizations: [Organization!]!` เปลี่ยนเป็น `Post.organization: Organization` เนื่องจากตำแหน่งหนึ่งเป็นขององค์กรเพียงองค์กรเดียว และสร้างหรือลบได้ผ่านตำแหน่งเท่านั้น การเชื่อมหรือยกเลิกการเชื่อมกับองค์กรที่มีอยู่แล้วให้ทำผ่าน `Organization.posts` แทน
- `BillVoteEvent.vote_events: [VoteEvent!]!` เปลี่ยนเป็น `BillVoteEvent.vote_event: VoteEvent` เนื่องจากการลงมติในร่างกฎหมายแต่ละครั้งตรงกับการลงมติเพียงครั้งเดียว `vote_event` จะเป็น `null` เมื่อยังไม่ได้จับคู่กับการลงมติ และสร้างหรือลบได้ผ่าน `BillVoteEvent` เท่านั้น การเชื่อมหรือยกเลิกการเชื่อมกับการลงมติที่มีอยู่แล้วให้ทำผ่าน `VoteEvent.bill_vote_events` แทน ซึ่งยังคงเป็น List

## 2026-11-09

**Breaking**

- ไม่สามารถกำหนด `BillMergeEvent.main_bill_id` ผ่าน `createBillMergeEvents` หรือ `updateBillMergeEvents` ได้อีกต่อไป ให้เชื่อมร่างหลักผ่าน `Bill.main_bill_merge_events` ใน `createBills` หรือ `updateBills` แทน

**Added**

- `Vote.voter_affiliations: [Organization!]!` และ `Organization.member_votes: [Vote!]!` เชื่อมการลงคะแนนเสียงกับพรรคหรือวุฒิสภาที่ผู้ลงคะแนนสังกัดในขณะนั้น
- `Vote.voter_affiliation_raw` แทนที่ `Vote.voter_party`
- `BillMergeEvent.main_bill: Bill` และ `Bill.main_bill_merge_events: [BillMergeEvent!]!` เชื่อมขั้นตอนการรวมร่างกับร่างหลัก แทนที่ `BillMergeEvent.main_bill_id`

**Deprecated**

- `Vote.voter_party` ให้ใช้ `Vote.voter_affiliation_raw` แทน
- `BillMergeEvent.main_bill_id` ให้ใช้ `BillMergeEvent.main_bill { id }` แทน

**Fixed**

- การเลือก `id` หรือ `created_at` จาก `edges.properties` จะไม่เกิดข้อผิดพลาด `Cannot return null for non-nullable field Relation.id` อีกต่อไป Relationship ที่เคยขาดค่าเหล่านี้ได้รับการเติมค่าแล้ว โดย `created_at` เป็นค่าโดยประมาณจาก Node ต้นทาง และ Relationship ใหม่จะได้รับค่าโดยอัตโนมัติ

## 2026-10-29

**Added**

- ระบุ `created_at` และ `updated_at` ว่าเป็น Field ภายในไม่ใช่วันที่ของเหตุการณ์จริง แนะนำผ่าน MCP Server กับ llms.txt เพื่อไม่ให้ AI Agent นำไปใช้แทน Field วันที่ของ Node เช่น `Bill.proposal_date`
- ภาษาไทยสำหรับ llm.txt (`/llms-th.txt` และ `/llms-full-th.txt`), MCP Tool `get-docs`, และ Resource `politigraph://docs/th` พร้อมคำแนะนำให้ AI Agent อ่านเอกสารภาษาไทยเมื่อผู้ใช้ถามเป็นภาษาไทย
- คำอธิบายของ `Person.id`, `Bill.id`, `VoteEvent.id` และ `Organization.id` ระบุ URL หน้าที่ตรงกันบน [Parliament Watch](https://parliamentwatch.wevis.info) และคำแนะนำของ MCP Server กับ llms.txt ให้ AI Agent อ้างอิง `links` และหน้าเหล่านี้เป็นแหล่งที่มา

## 2026-10-21

**Breaking**

- `Bill.lis_id` ถูกแทนที่ด้วย `Bill.lis_ids` และ Mutation `createBills` ต้องส่ง `lis_ids` แทน `lis_id`

**Added**

- `Bill.lis_ids` เนื่องจากร่างกฎหมายหนึ่งอาจจะมีหลาย id บนเว็บไซต์ lis.parliament เช่นในกรณีที่ร่างกฏหมายอยู่ในหลายสมันของสภา

## 2026-09-29

**Added**

- Query `timestamps` สำหรับดึงเวลา (UTC) ที่บอกความใหม่ของข้อมูล ได้แก่
  - `lastNodeUpdatedAt` เวลาที่ข้อมูลถูกเปลี่ยนแปลงล่าสุด
  - `lastVoteEventScrapedAt` เวลาที่ระบบอัตโนมัติดึงข้อมูลการลงมติ (`VoteEvent` และ `Vote`) สำเร็จล่าสุด
  - `lastBillScrapedAt` เวลาที่ระบบอัตโนมัติดึงข้อมูลร่างกฎหมายและเหตุการณ์ของร่างกฎหมายสำเร็จล่าสุด
- เพิ่มคำแนะนำของ MCP Server ให้ Agent ใช้ Query `timestamps` เพื่อตรวจสอบว่าข้อมูลเป็นปัจจุบันแค่ไหน

**Deprecated**

- `lastUpdatedAt` ให้ใช้ `timestamps { lastNodeUpdatedAt }` แทน

## 2026-09-24

**Breaking**

- เปลี่ยนชื่อ `Organization.motions` เป็น `Organization.considered_motions` คำอธิบายเดิมระบุผิดว่าเป็น "ญัตติที่เสนอในนามองค์กร" ในขณะที่ Field นี้หมายถึง "ญัตติที่พิจารณาในองค์กร" มาตลอด หากต้องการความหมายแรก ให้ใช้ `Organization.created_motions`
- `/graphql` ตอบกลับด้วย HTTP `400` แทน `200` เมื่อ Variable ไม่ตรงกับประเภทที่ประกาศไว้ โดย Body ที่เป็น `errors` ยังเหมือนเดิม

**Added**

- `Organization.created_motions` ญัตติที่เสนอในนามองค์กร (Back-reference ของ `CREATED_BY` เช่นเดียวกับ `Person.created_motions`)
- `Organization.considered_motions` ญัตติที่พิจารณาในองค์กร
- `/graphql` รองรับ Header `apollographql-client-name` และ `apollographql-client-version` ที่ไม่บังคับ เพื่อให้ Client ฝั่ง Server ระบุชื่อแอปพลิเคชันของตนได้
- MCP Tool `get-docs` สำหรับดึงสารบัญเอกสาร (`/llms.txt`) หรือหน้าเอกสารแต่ละหน้าในรูปแบบ Markdown เพื่อให้ Agent อ่านวิธีการจัดโครงสร้างข้อมูลและตัวอย่าง Query ได้

**Deprecated**

- `VoteEvent.bills` ให้ใช้ `VoteEvent.bill_vote_events.bills` แทน
- `Bill.requirement` และ `Motion.requirement` ไม่เคยมีข้อมูล และจะถูกลบในอนาคต
- `BillVoteEvent.pass_condition` ไม่เคยมีข้อมูล ให้ใช้ `BillVoteEvent.vote_events.pass_condition` แทน และจะถูกลบในอนาคต

## 2026-09-04

- `/llms.txt`, `/llms-full.txt` และเอกสารทุกหน้าในรูปแบบ `.md`
